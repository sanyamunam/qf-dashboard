# R3 notes — summary treatment brainstorm (fix 2)

Two structurally different treatments considered before committing:

**A. Tightened prose brief** (the R2 approach, better edited): one paragraph, lead sentence carrying the finding. Rejected: a paragraph is parsed, not scanned. The portfolio has five named areas the reader already knows; burying them in connective prose makes the reader do the mapping the layout should do. Fifteen seconds is not enough for 90 words of running text with nine linked figures.

**B. Headline finding + five theme rows — CHOSEN.** The conclusion leads as a serif headline ("Nothing is breaching. One programme is collapsing, and several 2026 targets look mis-set."). Beneath it, one row per thematic area: hue dot, theme name, one substantive fact with linked figures. The exception row (Social Progress) carries weight; the steady rows stay quiet. Reads top-to-bottom in a glance, all five areas guaranteed present by construction, no entity dominates because each gets exactly one line. The ask line closes.

The component is shared with L2 (`AiRead`): same surface, same type hierarchy, same avatar treatment; a 3px leading edge in the page's colour (Sidra on Thematic View, theme hue on L2) is the only difference. The gradient survives only where it signals AI authorship at small scale: spark glyphs, BOTaina's chrome.
